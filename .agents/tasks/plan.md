## Codebase Reality Check

**Confirmed file paths:**
- API server: `jev/server.py` (stdlib `ThreadingHTTPServer`, ~1780 lines, `do_GET`/`do_POST`/`do_DELETE`)
- CLI: `jev/cli.py` — `urai serve start` uses `--ctx` (default **2048**); `urai model` also uses `--ctx`
- llama-server lifecycle: `jev/serve_ctl.py` — `start(model_path, ctx=2048, ...)` passes `-c ctx` to llama-server
- Inference backend: `jev/backends.py` (`LlamaServerBackend`, `CloudAPIBackend`)
- Router: `jev/router.py` — `route()`, `pick_backend()`, L0–L4 tiers
- Tools: `jev/tools.py` — `run_code()` already exists (subprocess, no Docker/sandbox-image); `TOOLS` + `TOOL_SCHEMAS`
- Agent: `jev/agent.py` — `run_agent()`, `run_tool_call()`
- Swarm: `jev/swarm.py` — `run_swarm(tasks, max_workers)` — thread-based fan-out
- Vision: `jev/vision.py` — `see(image, question)` via Qwen2.5-VL-3B on llama-server
- Reason: `jev/reason.py` — `reason()`, `chain_of_thought()`, `verify_answer()`; Qwen3 `/think` mode
- Wiki: `jev/wiki.py` — three-tier memory; `wiki_add`, `wiki_search`, `wiki_get`
- Routines: `jev/routines.py` — `Routine` dataclass, `data/routines.json`
- Scheduler: `jev/sched.py` — `start()` daemon thread, ticks every 30s; watchdog
- Vibe: `jev/vibe.py` — `run_vibe()` tool-guarded write/bash loop
- Integrations: `jev/integrations.py` — currently a status report, NOT OAuth (new OAuth module needed)
- Studio: `jev/static/app.html` — 1499-line single-file PWA; vanilla JS; panels: Chat, Vibe, Wiki, Agents, Keys, Settings
- Dependencies manifest: `pyproject.toml` — core has zero deps; extras: `local`, `browser`, `vision`, `chart`, `memory`, `aws`
- Smoke test: `python3 scripts/smoke_urai.py` — must pass after every change
- No `pytest` installed in env; tests/ dir is empty; smoke script is the primary test

**Integration points between features:**
- `jev/events.py` (FEAT-7) is consumed by FEAT-4 (contemplate), FEAT-5 (vision grounding), FEAT-6 (goals) — implement events.py first
- `jev/sandbox.py` (FEAT-2) is separate from existing `run_code()` in tools.py — extend rather than replace
- `jev/server.py` and `jev/static/app.html` are touched by every feature — all server route additions go in one sequential pass to avoid conflicts
- `jev/tools.py` gets new tools in FEAT-2, FEAT-5, FEAT-6, FEAT-7, FEAT-8 — each FEAT appends to `TOOLS` dict and `TOOL_SCHEMAS` list
- `pyproject.toml` gets new deps in FEATs 2 (matplotlib already in `chart` extra), 8 (pymupdf), 9 (google-auth-oauthlib)

**Key discoveries:**
1. `ctx` default is **2048** in both `cli.py` and `serve_ctl.py` — must raise to 32768
2. `run_code()` in tools.py already does subprocess sandbox but lacks Docker, matplotlib image capture, and POST endpoint — FEAT-2 extends it
3. No `jev/events.py` exists — must create; it feeds goals.py and vibe/agent emitters
4. `jev/integrations.py` currently contains a status reporter, NOT OAuth — OAuth goes in a new `jev/integrations/` package
5. `data/goals/` directory path must be created by goals.py; `data/artifacts/` already created by tools.py
6. The Studio app.html already renders thinking traces, code blocks, and has a Settings panel — all new panels get added to the `sb-nav` sidebar and panel list

### FEAT-7: Observable Agent Event Log (implement first — used by FEAT-4, FEAT-5, FEAT-6)

**Decision:** New module `jev/events.py` with an in-memory ring buffer (per session_id). Use SSE at `GET /v1/agent/<session_id>/events`. Thread-safe dict of deques. `agent.py` and `vibe.py` call `events.emit()` at each tool call.

- [ ] 5. **Create `jev/events.py`**

      Implement:
      - `_store: dict[str, deque]` (session_id → deque of event dicts, max 500 per session, thread-safe)
      - `emit(session_id, type, agent_id, tool, input_summary, output_summary, status)` — appends `{timestamp, type, agent_id, tool, input_summary, output_summary, status}` dict
      - `get_events(session_id, since_ts=0)` — returns events newer than since_ts
      - `clear(session_id)` — removes session from store
      No external deps (stdlib only: `collections`, `threading`, `time`).

      Files: `jev/events.py` (new)
      Verify: `python3 -c "from jev.events import emit, get_events; emit('s1','tool_call','agent0','web_search','q=foo','results',True); print(get_events('s1'))"` — prints event dict.

- [ ] 6. **Wire `events.emit()` into `jev/agent.py` and `jev/vibe.py`**

      In `agent.py`, after `run_tool_call()` returns (in `run_agent()`), call `events.emit(session_id, "tool_call", agent_id="agent", tool=spec["tool"], input_summary=str(spec.get("args",""))[:200], output_summary=str(result)[:200], status=result.get("ok",False))`. Pass `session_id` through from `run_agent()` kwargs (default `""`). In `vibe.py`, emit similar events in `_exec_tool()`.

      Files: `jev/agent.py`, `jev/vibe.py`
      Verify: `python3 scripts/smoke_urai.py` passes.

- [ ] 7. **Add SSE endpoint `GET /v1/agent/<session_id>/events` in `jev/server.py`**

      In `do_GET`, match `p.startswith("/v1/agent/") and p.endswith("/events")`. Extract session_id. Stream SSE: on open send buffered events as `data: {...}\n\n` chunks, then hold connection open polling `get_events(sid, since_ts)` every 0.5s, write new events as SSE, exit when client disconnects (BrokenPipeError). Add `cancel` action: `POST /v1/agent/<session_id>/cancel` sets a cancellation flag per session (implemented as a set in `events.py`). Add Studio agent/vibe panel event log sidebar (collapsible): list of event rows with type icon, tool name, status badge, expandable input/output details.

      Files: `jev/server.py`, `jev/static/app.html`
      Verify: `python3 scripts/smoke_urai.py` passes; `curl -N http://localhost:8777/v1/agent/test/events` returns SSE stream.

### FEAT-4: Contemplating Mode (Parallel Multi-Agent Reasoning)

**Decision:** New module `jev/contemplate.py` using existing `swarm.py` for fan-out. Add `mode` param to `/v1/chat/completions`. Three seeds: analytical, creative, skeptical. Judge agent merges via another `run_agent()` call.

- [ ] 14. **Create `jev/contemplate.py`**

      Implement `contemplate(messages, max_tokens=1024, session_id="")`:
      - Define 3 system-prompt seeds: `{"analytical": "Focus on facts and logic...", "creative": "Explore novel angles...", "skeptical": "Challenge assumptions..."}`
      - Use `swarm.run_swarm([{task: prompt_text, system_override: seed} for seed in seeds], max_workers=3)` — needs small patch to `run_agent()` to accept `system_override` kwarg
      - Judge: call `run_agent(f"Merge these 3 answers into one best answer:\n1. {r0}\n2. {r1}\n3. {r2}")` 
      - Emit events via `events.emit()` for each parallel branch and the judge step
      - Returns `{answer, thinking_traces: [r0,r1,r2], judge_trace, elapsed_s}`

      Files: `jev/contemplate.py` (new), `jev/agent.py` (add `system_override` kwarg to `run_agent`)
      Verify: `python3 -c "from jev.contemplate import contemplate; r=contemplate([{'role':'user','content':'What is 2+2?'}]); print(r['answer'][:100])"` — returns merged answer.

- [ ] 15. **Add `mode` param to `/v1/chat/completions` in `jev/server.py`**

      In the `/v1/chat/completions` handler, extract `mode = body.get("mode", "instant")`. Modes: `"instant"` (current behavior), `"thinking"` (uses existing `reason.reason()`), `"contemplating"` (calls `contemplate.contemplate()`). Route accordingly before calling `route()`. Add `reasoning_mode` field to response body.

      Files: `jev/server.py`
      Verify: `python3 scripts/smoke_urai.py` passes; `curl -X POST .../v1/chat/completions -d '{"messages":[{"role":"user","content":"hi"}],"mode":"instant"}'` returns normal response.

- [ ] 16. **Add mode selector in Studio chat UI**

Show a progress indicator for contemplating mode ("Consulting 3 agents..."). Display thinking traces as collapsible `<details>` sections.

### FEAT-6: Proactive Goals Agent

**Decision:** New module `jev/goals.py` with file-based persistence in `data/goals/`. Goals have steps (multi-step plans created by `run_agent()`). Scheduler tick in `sched.py` calls `goals.tick()`. Approval queue blocks external actions. CLI uses existing `cli.py` pattern.

- [ ] 20. **Create `jev/goals.py`**

      Implement:
      - `Goal` dataclass: `{id, title, deadline, constraints, steps: [GoalStep], status, created_at}`
      - `GoalStep` dataclass: `{id, description, status, result, requires_approval, approved_at}`

      - `list_goals()`, `get_goal(id)`, `approve_step(goal_id, step_id)`, `delete_goal(id)`
      - Approval queue: pending steps with `requires_approval=True` saved in `data/goals/approval_queue.json`
      - External action heuristic: if step description contains keywords `browser`, `email`, `payment`, `send`, `post to`, `delete` → set `requires_approval=True`

      Files: `jev/goals.py` (new)
      Verify: `python3 -c "from jev.goals import list_goals, create_goal; print('ok')"` — imports cleanly.

- [ ] 21. **Wire `goals.tick()` into `jev/sched.py`**

      Files: `jev/sched.py`
      Verify: `python3 scripts/smoke_urai.py` passes.

- [ ] 22. **Add Goals API routes to `jev/server.py`**

      Add in `do_DELETE`: `DELETE /v1/goals/<id>`.

      Files: `jev/server.py`
      Verify: `python3 scripts/smoke_urai.py` passes.

## Complexity Flags

1. **PyMuPDF AGPL licensing** — use `pypdfium2` (Apache 2.0) as primary, `pymupdf` as optional fallback. Document clearly.
2. **Contemplate mode latency** — 3 parallel agents × ~10s each = ~10s wall time (parallel). The judge adds ~5s. Total ~15s. Warn users in UI.
3. **Docker sandbox** — Docker may not be installed on minimal VPS. The subprocess fallback must always work. FEAT-2 must never require Docker.
4. **Qwen2.5-VL bounding box format** — model outputs bbox in `[x1,y1,x2,y2]` as 0-1000 normalized or pixel coords depending on prompt. Normalize in `ground()` function. May need prompt tuning.
5. **integrations.py naming conflict** — step 29 must be committed before any other FEAT-9 step; the import change in server.py is a one-liner but must not be forgotten.
6. **1M context** — llama.cpp on CPU with 32K ctx uses ~4GB RAM per session. 128K with rope_scale=4 uses ~16GB. Document hardware requirements clearly. The "1M" claim is only achievable via cloud (Gemini 1.5 Pro). Be transparent in README/docs.
7. **Studio app.html size** — currently 1499 lines; adding 9 panels will push it to ~3000 lines. Consider splitting JS into `jev/static/app.js` after implementation. Not required for this task but note for future refactor.
