# Urai audit — 2026-10-15

## Critical findings
1. **Memory pressure / slow local teacher**
   - `llama-server` was running with `-c 4096` on an 8 GB VPS.
   - Under load it throttled to ~1.1 tok/s and distill chunks timed out at 300 s.
   - Fixed by restarting with `-c 2048 -fa on`; measured ~8.3 tok/s on a 16-token probe.
2. **Ghost model registry entries**
   - `qwen3-06b`, `qwen3-8b`, `qwen3-14b` were listed but files did not exist.
   - `DEFAULTS` referenced a missing `qwen2.5-0.5b` path and did not include `qwen3-4b`.
   - Registry now only lists disk-present models; coder models were added.
3. **Teacher timeouts**
   - `SelfTeacher` used 512 max tokens and the HTTP layer used a 300 s timeout.
   - Now 256 tokens for normal tasks, 512 for reasoning tasks, and 900 s timeout.
4. **Benchmark honesty**
   - API always returned zero token usage.
   - `LlamaServerBackend` now passes through real `usage` / `timings`.
   - `bench.py` now records token throughput and supports `--quick` and `--categories`.
5. **Secret hygiene**
   - No API tokens or private keys were found in the source tree.
   - OpenCode/OpenClaude logs contain previously pasted token material; treat those as exposed and rotate.
